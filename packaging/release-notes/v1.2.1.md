Three privacy and hardening fixes for album art, from the marketplace review: the widget fetches a cover only while it shows one, never from your own machine or local network, and Qt now only opens the helper's own copy of a cover. Nothing changes in how the widget looks or works for ordinary covers.

**Update** with `omarchy plugin update crmne.mpris`, or install with `omarchy plugin add https://github.com/crmne/omarchy-mpris.git --enable --yes`.

## Fixed

- **Turning off Show album art stops the cover requests too.** The setting hid the artwork, but the widget kept fetching each cover URL the player advertised. Covers are now fetched only while a widget shows artwork, so with Show album art off, or on a vertical bar where there is no artwork, the player's cover URL is never requested. By @crmne; thanks [HANCORE-linux](https://github.com/HANCORE-linux) for the report.
- **A player can no longer make the shell reach services on your machine or network.** The player chooses the cover URL, so it could point at anything reachable, such as a router page or a local development server. The album-art helper now connects only to public internet addresses: loopback, private, link-local and carrier-grade NAT addresses are refused before any connection is made, on every redirect hop, and the address checked is the one connected to. By @crmne; thanks [HANCORE-linux](https://github.com/HANCORE-linux) for the report.
- **Qt only ever opens the helper's copy of a cover on disk.** The helper used to check a player's cover file and then hand Qt the player's own path, so a file swapped in between could reach Qt unchecked. Covers on disk are now read once and written into the plugin's private cache, and Qt loads that copy. Every cover is also checked to be a PNG or JPEG of at most 3072 pixels a side and rewritten without its metadata, as in the lyrics plugin, so a small file cannot cost gigabytes to decode. By @crmne; thanks [HANCORE-linux](https://github.com/HANCORE-linux) for the report.

## Known limitations

- Covers served from your own machine or local network (a home media server, say) no longer show, and covers are not fetched through a proxy set in the environment.
- Covers larger than 3072 pixels a side, and covers in formats other than PNG and JPEG (such as GIF or WebP), are no longer shown.

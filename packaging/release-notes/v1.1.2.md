A safety fix for Media Controls + Album Art: a misbehaving album-art server can no longer exhaust the shell's memory. Nothing changes in how the widget looks or works.

**Update** with `omarchy plugin update crmne.mpris`, or install with `omarchy plugin add https://github.com/crmne/omarchy-mpris.git --enable --yes`.

## Fixed

- **Album art can no longer take the shell down.** The widget used to hand the cover URL from the player straight to Qt, which holds a whole http(s) response in memory before decoding it, however large. Covers are now downloaded by a small helper with a hard limit of 16 MiB and 20 seconds into a private cache under `~/.cache/omarchy/mpris/artwork`, and the widget loads them from there. Covers the player keeps on disk are shown only when they are regular files within the same limit, and the cover URL stays off the process list. Reported by @HANCORE-linux in [omacom/omarchy-plugin-marketplace#12065](https://github.com/omacom/omarchy-plugin-marketplace/issues/12065). By @crmne.

## Known limitations

- The album-art helper needs `/usr/bin/python3`.
- A cover larger than 16 MiB is not shown; the widget falls back to its music icon.
